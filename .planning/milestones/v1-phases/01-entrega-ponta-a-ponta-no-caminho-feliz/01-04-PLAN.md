<objective>
A API `notify-api` inteira da Fase 1: o cliente cria uma notificação e a acompanha pelo `Location`; publish sem confirmação vira PUBLISH_FAILED + 503; entrada inválida vira 400 Problem Details antes de qualquer gravação.

Purpose: é a metade "aceita = nunca perdida em silêncio" do core value. A API é dona dos estados PENDING e PUBLISH_FAILED e nunca grava nada depois do confirm (sem "QUEUED", para não correr contra o worker).
Output: pacote `dev.notifyhub.api` (config, web, application, messaging), `application.yml`/`application-demo.yml` e testes de fatia sem Docker.
</objective>
